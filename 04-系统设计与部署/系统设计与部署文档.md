# SmartLearn（鸿蒙智学业）系统设计与部署文档

> 版本 V3.3 · 2026-09-08 · HarmonyOS NEXT (API 23) + FastAPI + MySQL 8.0
>
> V3.3：新增专业级开场动画（Splash）与登录页玻璃拟态精修

## 一、系统概述

SmartLearn 是一个**端云一体化智慧教学平台**：HarmonyOS NEXT 原生 App（学生/教师/管理员三端）+
FastAPI 后端 + MySQL 数据库。覆盖「教-学-练-评-测-管-就业」全链路，内置 8 场景 AI 智能体与
数据统计看板。

| 端 | 技术 | 页面规模 | 核心能力 |
|---|---|---|---|
| 鸿蒙 App | ArkTS + ArkUI（IBest V2 组件库） | 63 页 | 三角色工作台、断点学习、防作弊考试、错题本、讨论区、私聊、签到、反馈中心 |
| 后端 | Python 3.10 + FastAPI + SQLAlchemy 2.0 (async) + JWT | 18 路由模块 / 46 接口域 | 五题型判分、快照固化、限流审计、Celery 定时聚合 |
| 数据库 | MySQL 8.0（utf8mb4）/ SQLite（开发） | 47 表 | 全外键约束 + 唯一索引 + 联合主键 |

## 四、部署指南

### 4.1 一键启动（推荐）

```powershell
cd smartlearn-backend
.\start_all.ps1          # 或双击 start_all.bat
```

自动执行：MySQL 服务检查 → 建库（utf8mb4）→ ORM 建表+基础种子 →
SQLite 全量数据迁移（保留 ID/外键）→ 真实数据补全 → FastAPI 启动。

常用参数：`-MysqlPassword 123456 -DbName smartlearn -BackendPort 8000 -SkipMigrate -SkipSeed`

### 4.2 手动部署

```powershell
# ① 建库
mysql -uroot -p -e "CREATE DATABASE smartlearn DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"

# ② 连接串写入 smartlearn-backend/.env
DATABASE_URL=mysql+aiomysql://root:密码@127.0.0.1:3306/smartlearn?charset=utf8mb4
JWT_SECRET=<openssl rand -hex 32>

# ③ 依赖 + 建表 + 种子
python -m venv .venv && pip install -r requirements.txt
python -c "import asyncio; from app.database import init_db; asyncio.run(init_db())"

# ④ 数据迁移/补全（幂等，可重跑）
python migrate_to_mysql.py --db smartlearn --password 密码   # SQLite→MySQL 全量
python seed_real_data.py                                     # 真实数据（双库自适应）

# ⑤ 启动
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 4.3 App 安装（模拟器/真机）

```powershell
hdc install -r entry-default-unsigned.hap     # 生产签名需用 DevEco Studio 签名后 .hap
hdc shell aa start -a EntryAbility -b com.smartlearn.app
```

DevEco Studio 内：File → Open → 选择工程根目录，设备管理器启动模拟器，Run 'entry'。

### 4.4 Docker Compose（可选容器化）

`docker-compose.yml` 提供 mysql + redis + backend 三服务编排；`smartlearn-backend/Dockerfile`
为多阶段构建（pip 层缓存 + 非 root 运行）。

### 5.3 已修复缺陷记录

**教研区发帖 MySQL 500（外键 1452）**：
教研区用 `course_id=0` 哨兵区分学生讨论与教师教研空间。SQLite 建表不生成物理外键所以从未暴露；
MySQL 有真实外键 `discussion_post.course_id → course.id`，id=0 无对应行导致插入失败。
修复三件套：
1. `database.py` init_db 幂等插入 **id=0 哨兵课程行「教研专区」**；MySQL 下先
   `SET SESSION sql_mode=NO_AUTO_VALUE_ON_ZERO`（否则 AUTO_INCREMENT 列会把显式 0
   静默替换成自增值）；并补 created_at/updated_at（MySQL 无默认值报 1364）
2. `courses.py` 课程列表 `WHERE id != 0` 过滤，避免学生看到哨兵行假课程
3. 生产库/示例库均补哨兵行；SQLite 亦同步（行为一致）

## 六、教研区哨兵设计（数据模型要点）

```
course 表
├─ id 1..5   真实课程（学生可见）
└─ id 0      教研专区（status=0，列表层过滤，discussion_post.course_id 外键挂靠）
discussion_post.course_id = 0  → 教师教研帖（TEACHER/ADMIN 才能读写，学生 403）
discussion_post.course_id > 0  → 课程讨论（广场聚合，排除 0）
```

幂等保障：init_db 每次启动检查哨兵（INSERT 冲突即跳过）；迁移脚本保留该行；
`GET /courses` 恒过滤。
