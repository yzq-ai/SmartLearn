# 鸿蒙智学业（SmartLearn）AI 智能体说明文档

> 本文档说明项目中大语言模型（LLM）接入的完整方案：AI 功能清单、输入数据、知识来源、处理过程、输出结果与审核方式。对应项目要求第 6、11、12、13 条。

## 一、AI 功能总览（8 大场景，全部深度绑定业务）

| # | 场景 | 入口（端侧页面） | 结合的业务模块 | 是否绑定业务数据 |
|---|---|---|---|---|
| 1 | **课程问答 RAG** | CourseDetail → AI 问答 | 课程/章节/小节内容 | ✅ 检索本课程资料作答 |
| 2 | **内容摘要** | AISummary 页 | 任意课程内容 | ✅ 压缩课程正文为 300 字+3 要点 |
| 3 | **学习计划生成** | StudyPlan 页 | 错题记录+掌握度画像 | ✅ 按弱项生成 3 周里程碑计划 |
| 4 | **题目生成（DRAFT 审核流）** | QuestionBank → AI 出题 | 题库/知识点 | ✅ 生成后进 DRAFT，教师审核后才入库 |
| 5 | **错题分析** | WrongBook → 🤖 AI 分析 | 错题记录 | ✅ 输入题干+我的答案+正确答案 |
| 6 | **简历优化** | ResumeEdit → ✨ AI 优化 | 简历内容 | ✅ 逐条 Diff 建议，采纳才写入 |
| 7 | **岗位推荐解释** | Home 就业 Tab → 🤖 解释匹配 | 岗位匹配引擎 | ✅ 解释匹配分数的构成与 gap |
| 8 | **面试模拟** | 简历页 → 面试模拟 | 简历+目标岗位 | ✅ 生成针对性面试问答训练 |

**非通用聊天窗口的证明**：8 个场景无一例外以业务实体（课程/错题/简历/岗位/画像）为输入上下文，输出直接回写或辅助对应模块的业务操作（错题分析结果可反馈掌握度、简历建议采纳回填表单、AI 出题进入题库审核队列、岗位解释基于规则引擎分数而非 LLM 自由发挥）。

## 二、模型接入配置（环境变量）

后端使用 **OpenAI 兼容协议**接入 LLM，通过环境变量一键切换供应商。**DeepSeek 配置示例**（写入 `smartlearn-backend/.env`）：

```env
# DeepSeek（用户当前计划接入的模型）
LLM_API_KEY=sk-你的deepseek密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

# 限流（内置）
AI_REQUESTS_PER_MINUTE=10
AI_DAILY_LIMIT=200
```

读取位置：`app/core/config.py`
```python
llm_api_key: str = Field(default="", validation_alias="LLM_API_KEY")
llm_base_url: str = Field(default="https://api.openai.com/v1", validation_alias="LLM_BASE_URL")
llm_model: str = Field(default="gpt-4o-mini", validation_alias="LLM_MODEL")
```

> 兼容性说明：任何 OpenAI 兼容网关（DeepSeek / GLM / Qwen / 本地 vLLM）只需改这三个变量，代码零改动。**未配置密钥时系统自动降级为内置规则引擎**（纯函数，无外部请求），保证演示可用。

## 三、各场景输入数据与知识来源

### 1. 课程问答（RAG 检索增强）
- **输入**：学生提问 + 当前 course_id
- **知识来源**：该课程全部章节/小节文本内容（数据库实时检索），向量库（memory/qdrant 可配）
- **输入样例**：`"仅根据以下课程资料回答问题，资料未覆盖时明确说明。资料：{检索片段} 问题：{学生提问}"`

### 2. 内容摘要
- **输入**：章节正文（教师发布的课程内容）
- **知识来源**：课程内容本身，无外部知识
- **输出契约**：`{"summary": "≤300字", "key_points": ["要点1", "要点2", "要点3"]}`

### 3. 学习计划
- **输入**：学生错题记录（题目/知识点/错误次数）+ 知识点掌握度
- **知识来源**：学习行为数据（错题表 + 掌握度表 + 画像）
- **输出**：3 周里程碑计划（每周目标知识点 + 推荐课程）

### 4. 题目生成（先审后入）
- **输入**：course_id + kp_ids（知识点）+ 难度 + 题型
- **知识来源**：知识点名称与课程大纲
- **输出**：`{text, options, answer, analysis, difficulty, score}` → **status=DRAFT**，不直接入库

### 5. 错题分析
- **输入**：`{question: 题干, my_answer: 我的答案, correct: 正确答案}`
- **知识来源**：题目解析（analysis 字段）
- **输出契约**：`{"cause_category": "概念混淆|计算错误|审题失误", "analysis": "错因分析", "suggestion": "改进建议"}`

### 6. 简历优化
- **输入**：简历五字段（name/education/skills/projects/self_eval）+ 目标岗位
- **知识来源**：简历原文 + 岗位技能要求
- **输出契约**：`{"items": [{"original": "原文", "suggestion": "建议稿", "reason": "理由", "type": "技能|经历|表达"}]}`
- **特殊机制**：**逐条 Diff 展示 + 学生逐条采纳**，AI 绝不直接覆盖原文

### 7. 岗位推荐解释
- **输入**：岗位标题、技能要求、**规则引擎计算的匹配分**（match_score）、已匹配/缺口标签
- **知识来源**：匹配引擎结果（**LLM 只解释、不改分数**）+ gap 反查补强课程
- **输出**：`{explanation: "为何是这个分数", suggestions: ["补强课程1", ...]}`

### 8. 面试模拟
- **输入**：简历内容 + 目标岗位技能
- **知识来源**：简历 + 岗位要求
- **输出**：结构化面试问答对（3-5 组），供学生自测

## 四、处理过程（统一流水线）

```
学生/教师请求
    │
    ▼
┌─────────────────────────────────────────────┐
│ 1. 端侧预检：登录态（JWT）+ 角色权限（RBAC）    │
│    + 限流（10 次/分钟、200 次/天）             │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 2. 双重脱敏（app/services/ai_security.py）     │
│    手机号 → [redacted]                        │
│    邮箱   → [redacted]                        │
│    身份证号 → [redacted]                       │
│    + 敏感词扫描（敏感词库，命中即拦截）           │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 3. 业务上下文组装（RAG 检索 / 错题 / 简历等）    │
│    组装为带输出契约的 Prompt                    │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 4. LLM 调用（OpenAI 兼容客户端）                │
│    已配置密钥 → deepseek-chat 等                │
│    未配置密钥 → 内置规则引擎降级                 │
│    超时/异常 → 同样降级，不阻塞业务              │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 5. 输出过滤（输出必须符合 JSON 契约）            │
│    二次脱敏（防止模型复述隐私）                   │
│    DRAFT 场景标记待审状态                        │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 6. 审计落库（ai_chat_log 表）                  │
│    记录：用户/场景/输入摘要/输出/来源/耗时        │
│    赞踩反馈（👍👎）回写 log                      │
└─────────────────────────────────────────────┘
    │
    ▼
  返回端侧渲染（结构化卡片/弹窗/表单回填）
```

## 五、输出结果与端侧呈现

| 场景 | 呈现形式 |
|---|---|
| 课程问答 | 对话气泡 + 引用来源标注（grounded 标记） |
| 内容摘要 | 摘要卡 + 3 要点列表 |
| 学习计划 | 3 周里程碑时间线 |
| 题目生成 | DRAFT 队列卡（教师审核后才入正式题库） |
| 错题分析 | 分析弹窗（错因分类徽章 + 建议）+ 👍👎 反馈 |
| 简历优化 | **逐条 Diff 卡**：原文（删除线）→ 建议稿 → 理由 + 采纳/忽略按钮 |
| 岗位解释 | AlertDialog 弹窗（分数构成 + 补强课程清单） |
| 面试模拟 | 问答对卡片（问题 + 参考回答，可展开） |

## 六、审核方式（四层）

1. **输入审核**：
   - 敏感词过滤（讨论区/简历/岗位/活动全链路，敏感词库管理端可维护）
   - 脱敏正则（手机/邮箱/身份证进 LLM 前已替换）
2. **过程审核**：
   - 限流（10/min、200/day）防止滥用与费用失控
   - 审计日志（每次 AI 调用全量落库 ai_chat_log，含输入/输出/耗时/来源）
3. **输出审核**：
   - JSON 契约校验（不符合契约的结果被拒绝呈现）
   - 二次脱敏（模型输出再过一遍隐私正则）
   - **DRAFT 工作流**：AI 生成题目一律进 DRAFT 状态，**教师审核通过后才进入正式题库**
4. **人工复核**：
   - 管理端「操作日志」可查全部 AI 调用记录
   - 赞踩反馈数据供运营评估 AI 质量，持续优化 Prompt
   - 简历优化必须学生**逐条人工采纳**，绝不自动覆盖

## 七、降级策略（无 LLM 密钥时）

| 场景 | 降级实现 |
|---|---|
| 课程问答 | 关键词匹配课程资料，返回最相关片段 |
| 摘要 | 首句提取 + 高频词要点 |
| 学习计划 | 按掌握度排序弱项生成固定模板计划 |
| 错题分析 | 按题型给出错因分类与通用建议 |
| 简历优化 | 规则引擎（动词量化/STAR 法则检查）生成建议 |
| 岗位解释 | 基于匹配标签直接生成解释文案 |

> 降级模式保证：演示环境无需任何 API 密钥即可走通全部 8 个 AI 场景闭环。

## 八、隐私与数据安全（对应要求 13）

- **进 LLM 前脱敏**：手机号/邮箱/身份证号正则替换为 `[redacted]`，敏感词命中直接拦截
- **出 LLM 后二次脱敏**：防止模型复述或生成隐私内容
- **审计全量落库**：ai_chat_log 记录每次调用（谁、何时、什么场景、输入摘要、输出、来源、耗时）
- **学生隐私保护**：
  - AI 输入仅包含业务必要字段（错题分析不传姓名，简历优化只传简历内容本身）
  - 学习数据仅本人与授权教师可见（RBAC 粒度到接口）
- **考试数据保护**：
  - 试卷快照固化（开考瞬间题目锁定，防开考后题库被改）
  - 切屏监控（switch_count 记录，异常强制收卷）
  - 成绩/答案仅本人和教师可见
- **就业信息管理**：
  - 岗位/企业先审后发（review_status 工作流）
  - 简历快照随投递固化（企业查看的是投递瞬间版本）
  - 学生投递记录仅本人可见
